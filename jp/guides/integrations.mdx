Google は、ドライブ、Gmail、スプレッドシート、カレンダー、マップなど、コアサービスの大部分を、任意のアプリケーションから呼び出せる REST API として公開しています。最初の API リクエストを書く前に、アプリの認証方法を決定する必要があります。公開データ用のシンプルな API キー、サインイン済みユーザーの代理で動作するための OAuth 2.0、または自動化されたサーバー間ワークフロー用のサービスアカウントです。このガイドでは、各オプションを説明し、それぞれのセットアップ手順を案内します。

## 認証方式を選ぶ

適切な認証方式は、統合が何を行い、誰のデータにアクセスするかによって決まります。

| 認証方式 | 典型的なユースケース | 使用する状況 | ユーザー同意が必要か |
|---|---|---|---|
| **API キー** | 公開データの読み取り（例: マップ、YouTube メタデータ） | アプリが非機密で公開されているリソースにアクセスする | 不要 |
| **OAuth 2.0** | サインインした Google ユーザーの代理で動作 | アプリがユーザーのドライブファイル、Gmail、カレンダーなどを読み書きする | 必要 — ユーザーが権限を付与する必要あり |
| **サービスアカウント** | 人間のユーザーが関与しないサーバー間の自動化 | バックエンドジョブ、データパイプライン、組織所有のリソースへのアクセス | 不要 |

## OAuth 2.0 フロー

OAuth 2.0 は、ユーザーがパスワードを共有することなく、アプリケーションに Google データへの限定的なアクセスを付与するための標準です。認可コードフローを実装する手順は以下のとおりです。

<Steps>
  <Step title="Cloud Console で OAuth クライアント ID を作成する">
    [Google Cloud Console](https://console.cloud.google.com) を開き、**APIs & Services → Credentials** に移動して、**Create Credentials → OAuth client ID** をクリックします。**Web application**（またはアプリに合ったプラットフォーム）を選択し、認可済みリダイレクト URI を追加します。
  </Step>
  <Step title="同意画面を構成する">
    **APIs & Services → OAuth consent screen** に移動します。アプリ名、サポートメールアドレス、アプリが要求するスコープを入力します。スコープは、アプリがアクセスできる Google データを正確に定義します — アプリが必要とする最小限のスコープだけを要求してください。
  </Step>
  <Step title="ユーザーを Google の認可 URL にリダイレクトする">
    ユーザーが自分の Google アカウントを接続したい場合、`client_id`、要求する `scope`、`redirect_uri`、`response_type=code` を含めて Google の認可エンドポイントにリダイレクトします。Google は構成した同意画面を表示します。
  </Step>
  <Step title="認可コードをトークンと交換する">
    ユーザーが承認した後、Google は短命の `code` パラメーターを付けて `redirect_uri` にリダイレクトします。code、`client_id`、`client_secret`、`redirect_uri` を使って `https://oauth2.googleapis.com/token` にサーバーサイドで POST リクエストを行い、`access_token` と（`offline` アクセスを要求した場合は）`refresh_token` を受け取ります。
  </Step>
  <Step title="Bearer トークンで API を呼び出す">
    すべての API リクエストの `Authorization` ヘッダーに `access_token` を含めます。アクセストークンは 1 時間で期限切れになります — `refresh_token` を使って、ユーザーに再度プロンプトを表示することなく自動的に新しいトークンを取得してください。
  </Step>
</Steps>

## サービスアカウント

サービスアカウントは、個々のユーザーではなくアプリケーションに属する特別な Google アカウントです。秘密鍵で認証するため、バックエンドサービス、スケジュールされたジョブ、対話的なユーザーがいないワークフローに最適です。

1. Cloud Console で **IAM & Admin → Service Accounts** に移動し、**Create Service Account** をクリックします。
2. アカウントに分かりやすい名前を付け、任意で必要な最小権限を反映する IAM ロールを付与します。
3. サービスアカウントを開き、**Keys** タブに移動して **Add Key → Create new key** をクリックし、**JSON** を選択します。キーファイルをすぐにダウンロードしてください — 再度ダウンロードすることはできません。
4. JSON キーを安全に保管し（ベストプラクティスは[セキュリティガイド](/guides/security)を参照）、サーバーサイドのコードで適切な Google クライアントライブラリを使用して読み込みます。

サービスアカウントに特定の Google ドライブフォルダやスプレッドシートファイルへのアクセスを許可するには、そのリソースをサービスアカウントのメールアドレス（Cloud Console で確認可能）に対して、人間のユーザーに共有するのと同じように共有してください。

## API の呼び出し

アクセストークンが手に入ったら、HTTP リクエストの `Authorization` ヘッダーに `Bearer` トークンとして付与します。以下は、ユーザーの Google ドライブ内のファイルをリストする例です。

```bash
curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  "https://www.googleapis.com/drive/v3/files"
```

`YOUR_ACCESS_TOKEN` を、OAuth フローで受け取ったトークンや、サービスアカウントキーで JWT を署名して得たトークンに置き換えてください。レスポンスは、認証されたプリンシパルがアクセスできるファイルのリストを含む JSON オブジェクトです。

<Note>
トークンスコープ、リフレッシュフロー、トークンの取り消し処理の完全なリファレンスについては、[認証 API リファレンス](/api/authentication)を参照してください。
</Note>
