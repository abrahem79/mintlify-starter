你向 Google REST API 发出的每个请求都必须经过身份验证。Google 支持三种主要的身份验证机制：用于访问公共数据的 API 密钥、用于代表用户操作的 OAuth 2.0 Bearer 令牌，以及用于服务器到服务器集成的服务账户凭据。选择合适的机制取决于你需要访问的数据以及流程中是否涉及人类用户。

## API 密钥

API 密钥是最简单的身份验证方法。它们向 Google 标识你的项目，但不携带任何用户上下文，因此只适用于访问**公开可用数据**的 API（例如 Programmable Search API）。

在每个请求上将 API 密钥作为 `key` 查询参数传递：

```http
GET https://www.googleapis.com/customsearch/v1?q=example&key=YOUR_API_KEY&cx=YOUR_CX
```

**curl 示例：**

```bash
curl "https://www.googleapis.com/customsearch/v1?q=openai&key=YOUR_API_KEY&cx=YOUR_CX_ID"
```

<Tip>
  在 [Google Cloud Console](https://console.cloud.google.com/apis/credentials) 中生成并管理你的 API 密钥。将每个密钥限制在特定 API 和引荐 URL 上，以在密钥泄露时限制其影响范围。
</Tip>

## OAuth 2.0 Bearer 令牌

当你的应用需要访问或修改**用户拥有的数据**——例如 Google Drive 中的文件、Gmail 消息或日历事件——时，你必须使用 OAuth 2.0。用户完成 OAuth 授权流程后，你的应用会收到一个访问令牌，将其包含在每个请求的 `Authorization` 头中。

```http
Authorization: Bearer ACCESS_TOKEN
```

访问令牌默认在 **3600 秒（1 小时）** 后过期。你的应用应存储随附的刷新令牌，并使用它在无需再次提示用户的情况下获取新的访问令牌。详情请参阅下面的[令牌刷新](#token-refresh)。

**curl 示例：**

```bash
curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  "https://www.googleapis.com/drive/v3/files"
```

## 服务账户凭据

服务账户是属于某个应用而非个人用户的特殊 Google 账户。它们专为**服务器到服务器**场景设计——例如，一个按计划从 Google Sheets 读取数据且没有任何用户交互的后端任务。

要以服务账户身份进行身份验证：

1. 在 [Google Cloud Console](https://console.cloud.google.com/iam-admin/serviceaccounts) 中，创建一个服务账户并下载其 JSON 密钥文件。
2. 授予服务账户所需的 IAM 角色（例如 `roles/drive.reader`）。
3. 使用 Google 客户端库或已签名的 JWT，将密钥换取一个短期访问令牌。

**示例：使用 curl 将服务账户密钥换取访问令牌**

```bash
# 1. Install the google-auth-library or use the oauth2 token endpoint directly.
# Below shows the two-legged JWT flow at its simplest using Python's google-auth library.
# Install: pip install google-auth requests

python3 - <<'EOF'
from google.oauth2 import service_account
import google.auth.transport.requests

SCOPES = ["https://www.googleapis.com/auth/drive.readonly"]
credentials = service_account.Credentials.from_service_account_file(
    "service-account-key.json", scopes=SCOPES
)
request = google.auth.transport.requests.Request()
credentials.refresh(request)
print("Access token:", credentials.token)
EOF
```

获得访问令牌后，将其作为 Bearer 令牌传递，方式与 OAuth 2.0 完全相同：

```bash
curl -H "Authorization: Bearer ACCESS_TOKEN" \
  "https://www.googleapis.com/drive/v3/files"
```

<Warning>
  安全存储你的服务账户 JSON 密钥文件，切勿将其提交到源代码管理。如果你怀疑密钥已被泄露，请立即轮换。
</Warning>

## 作用域

OAuth 2.0 作用域精确定义访问令牌授予的权限。你在授权步骤中请求作用域，用户会在 Google 的授权页面上看到它们列出。仅请求你的应用真正需要的作用域——请求过于宽泛的作用域会削弱用户信任，并可能在应用验证时被拒绝。

| 作用域 | 授予的访问权限 |
|-------|----------------|
| `https://www.googleapis.com/auth/drive.readonly` | 只读访问用户 Google Drive 中的所有文件。 |
| `https://www.googleapis.com/auth/drive` | 完整的读写访问用户的 Google Drive。 |
| `https://www.googleapis.com/auth/gmail.readonly` | 只读访问用户的 Gmail 消息和设置。 |
| `https://www.googleapis.com/auth/calendar` | 完整的读写访问用户的 Google 日历。 |
| `openid` | 通过 OpenID Connect 对用户进行身份验证并获取稳定的用户 ID。 |
| `email` | 访问用户的主 Google 账户邮箱地址。 |
| `profile` | 访问用户的基本资料信息（姓名、头像、区域设置）。 |

## 令牌刷新

访问令牌过期后，通过向 Google 令牌端点发送 `POST` 请求，将刷新令牌换取新令牌：

```bash
curl -X POST https://oauth2.googleapis.com/token \
  -d "client_id=CLIENT_ID" \
  -d "client_secret=CLIENT_SECRET" \
  -d "refresh_token=REFRESH_TOKEN" \
  -d "grant_type=refresh_token"
```

成功的响应包含新的访问令牌及其到期时间：

```json
{
  "access_token": "ya29.A0ARrdaM...",
  "expires_in": 3600,
  "token_type": "Bearer"
}
```

| 字段 | 描述 |
|-------|-------------|
| `access_token` | 在后续 API 请求中使用的新 Bearer 令牌。 |
| `expires_in` | 令牌过期前的秒数（通常为 `3600`）。 |
| `token_type` | 始终为 `"Bearer"`。 |

存储新的 `access_token` 并在应用中替换先前的令牌。刷新令牌本身在用户撤销访问权限或被 Google 因其他原因失效之前仍然有效。

<Warning>
  切勿将你的 OAuth `client_secret` 嵌入客户端代码（JavaScript 包、移动应用或公共仓库）。一旦泄露，攻击者可以冒充你的应用、劫持 OAuth 流程并代表你访问用户数据。始终在安全的后端服务器上进行令牌交换。
</Warning>
