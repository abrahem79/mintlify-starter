Google은 핵심 서비스 대부분 — Drive, Gmail, Sheets, Calendar, Maps 등 — 을 모든 애플리케이션이 호출할 수 있는 REST API를 통해 노출합니다. 첫 API 요청을 작성하기 전에, 앱이 어떻게 인증할지 결정해야 합니다: 공개 데이터에는 간단한 API 키, 로그인한 사용자를 대신한 작업에는 OAuth 2.0, 자동화된 서버 간 워크플로에는 서비스 계정입니다. 이 가이드는 각 옵션을 설명하고 각각의 설정 단계를 안내합니다.

## 인증 방식 선택

올바른 인증 방식은 통합이 무엇을 하고 누구의 데이터에 접근하는지에 따라 달라집니다.

| 인증 방식 | 일반적인 사용 사례 | 사용 시점 | 사용자 동의 필요 |
|---|---|---|---|
| **API 키** | 공개 데이터 읽기(예: Maps, YouTube 메타데이터) | 앱이 민감하지 않고 공개적으로 사용 가능한 리소스에 접근 | 아니요 |
| **OAuth 2.0** | 로그인한 Google 사용자를 대신해 작업 | 앱이 사용자의 Drive 파일, Gmail, Calendar 등을 읽거나 씀 | 예 — 사용자가 권한을 부여해야 함 |
| **서비스 계정** | 사람 사용자 없이 서버 간 자동화 | 백엔드 작업, 데이터 파이프라인, 조직이 소유한 리소스에 접근 | 아니요 |

## OAuth 2.0 흐름

OAuth 2.0은 사용자가 비밀번호를 공유하지 않고 여러분의 애플리케이션에 자신의 Google 데이터에 대한 제한된 접근을 부여할 수 있게 해주는 표준입니다. Authorization Code 흐름을 구현하려면 다음 단계를 따르세요.

<Steps>
  <Step title="Cloud Console에서 OAuth 클라이언트 ID 만들기">
    [Google Cloud Console](https://console.cloud.google.com)을 열고 **APIs & Services → Credentials**로 이동한 다음 **Create Credentials → OAuth client ID**를 클릭하세요. **Web application**(또는 앱과 일치하는 플랫폼)을 선택하고 승인된 리디렉션 URI를 추가하세요.
  </Step>
  <Step title="동의 화면 구성">
    **APIs & Services → OAuth consent screen**으로 이동하세요. 앱 이름, 지원 이메일, 앱이 요청할 스코프를 입력하세요. 스코프는 앱이 어떤 Google 데이터에 접근할 수 있는지 정확히 정의합니다 — 앱에 필요한 최소한만 요청하세요.
  </Step>
  <Step title="Google 인증 URL로 사용자 리디렉션">
    사용자가 Google 계정을 연결하려고 할 때, `client_id`, 요청된 `scope`, `redirect_uri`, `response_type=code`와 함께 Google의 인증 엔드포인트로 리디렉션하세요. Google은 구성한 동의 화면을 표시합니다.
  </Step>
  <Step title="인증 코드를 토큰으로 교환">
    사용자가 승인하면 Google이 짧은 수명의 `code` 파라미터와 함께 여러분의 `redirect_uri`로 리디렉션합니다. 코드, `client_id`, `client_secret`, `redirect_uri`와 함께 서버 측 POST 요청을 `https://oauth2.googleapis.com/token`으로 보내 `access_token`과 (`offline` 접근을 요청한 경우) `refresh_token`을 받으세요.
  </Step>
  <Step title="Bearer 토큰으로 API 호출">
    모든 API 요청의 `Authorization` 헤더에 `access_token`을 포함하세요. 액세스 토큰은 한 시간 후에 만료됩니다 — `refresh_token`을 사용해 사용자에게 다시 프롬프트하지 않고 자동으로 새 토큰을 얻으세요.
  </Step>
</Steps>

## 서비스 계정

서비스 계정은 개별 사용자가 아니라 여러분의 애플리케이션에 속하는 특별한 Google 계정입니다. 개인 키로 인증하므로 백엔드 서비스, 예약 작업, 그리고 대화형 사용자가 없는 모든 워크플로에 이상적입니다.

1. Cloud Console에서 **IAM & Admin → Service Accounts**로 이동하고 **Create Service Account**를 클릭하세요.
2. 계정에 서술적인 이름을 지정하고, 선택적으로 필요한 최소 권한을 반영하는 IAM 역할을 부여하세요.
3. 서비스 계정을 열고 **Keys** 탭으로 이동해 **Add Key → Create new key**를 클릭한 다음 **JSON**을 선택하세요. 키 파일을 즉시 다운로드하세요 — 다시 다운로드할 수 없습니다.
4. JSON 키를 안전하게 보관하고([Security 가이드](/guides/security)에서 모범 사례 참조), 적절한 Google 클라이언트 라이브러리를 사용해 서버 측 코드에서 로드하세요.

서비스 계정이 특정 Google Drive 폴더나 Sheets 파일에 접근할 수 있게 하려면, 사람 사용자와 공유할 때와 동일하게 서비스 계정의 이메일 주소(Cloud Console에서 확인 가능)로 해당 리소스를 공유하세요.

## API 호출

액세스 토큰이 있으면, HTTP 요청의 `Authorization` 헤더에 `Bearer` 토큰으로 첨부하세요. 다음은 사용자의 Google Drive 파일을 나열하는 예시입니다:

```bash
curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  "https://www.googleapis.com/drive/v3/files"
```

`YOUR_ACCESS_TOKEN`을 OAuth 흐름에서 받았거나 서비스 계정 키로 JWT에 서명해 받은 토큰으로 바꾸세요. 응답은 인증된 주체가 접근할 수 있는 파일 목록이 포함된 JSON 객체입니다.

<Note>
토큰 스코프, 리프레시 흐름, 토큰 취소 처리에 대한 전체 레퍼런스는 [Authentication API 레퍼런스](/api/authentication)를 참조하세요.
</Note>
