리소스가 변경되었는지 확인하기 위해 API를 반복적으로 폴링하는 대신, Google의 푸시 알림 시스템을 사용하여 변경이 발생하는 순간 Google이 여러분의 서버를 호출하게 할 수 있습니다. 여러분이 제어하는 HTTPS 엔드포인트를 가리키는 **watch 채널**을 등록하면, 지켜보는 리소스가 생성, 업데이트, 삭제될 때마다 Google이 해당 엔드포인트로 `POST` 요청을 보냅니다. 푸시 알림은 Google Drive, Gmail, Calendar 및 여러 다른 API에서 사용할 수 있습니다.

<Warning>
  웹훅 엔드포인트는 유효한 인증서로 HTTPS를 통해 서비스되어야 **합니다**. Google은 일반 HTTP URL로 알림을 전달하지 않습니다. 또한 엔드포인트는 **10초** 이내에 HTTP `200 OK`로 응답해야 합니다 — 시간 초과된 응답은 실패로 처리되며 Google이 해당 채널로 알림 전달을 중단하게 만들 수 있습니다.
</Warning>

## 푸시 알림 작동 방식

흐름은 네 단계로 진행됩니다:

1. **등록** — 애플리케이션이 모니터링하고자 하는 리소스의 `watch` 메서드를 호출하여, 엔드포인트 URL과 고유한 채널 ID를 제공합니다.
2. **동기화** — Google이 초기 알림(`X-Goog-Resource-State: sync`)으로 채널을 확인합니다.
3. **수신** — 리소스가 변경될 때마다 Google이 여러분의 엔드포인트로 `POST` 요청을 보냅니다.
4. **갱신 또는 중지** — 채널에는 만료 시간이 있습니다. 만료 전에 다시 등록해야 하며, 더 이상 필요하지 않으면 명시적으로 중지해야 합니다.

## Watch 채널 등록

아래 예시는 Google Drive의 모든 파일에 대한 watch를 등록합니다. 다른 API도 동일한 패턴을 따르며 엔드포인트 경로만 다릅니다.

**엔드포인트**

```http
POST https://www.googleapis.com/drive/v3/files/watch
```

### 요청 본문 파라미터

<ParamField body="id" type="string" required>
  이 채널을 식별하기 위해 여러분이 생성하는 UUID 또는 기타 고유 문자열입니다. Google은 모든 알림에서 이 값을 그대로 반환하므로, 이를 사용해 알맞은 핸들러로 라우팅할 수 있습니다.
</ParamField>

<ParamField body="type" type="string" required>
  알림의 전달 방식입니다. HTTPS 푸시 전달의 경우 반드시 `"web_hook"`이어야 합니다.
</ParamField>

<ParamField body="address" type="string" required>
  웹훅 엔드포인트의 완전히 정규화된 HTTPS URL입니다. Google이 이 URL로 알림을 `POST`합니다.
</ParamField>

<ParamField body="expiration" type="integer">
  채널이 만료되어야 할 시점을 **밀리초** 단위로 지정하는 Unix 타임스탬프입니다. 생략하면 Google이 기본 만료(일반적으로 최대 7일)를 적용합니다. 이 시간 전에 채널을 다시 등록해야 알림 누락을 피할 수 있습니다.
</ParamField>

### 요청 예시

```bash
curl -X POST \
  "https://www.googleapis.com/drive/v3/files/watch" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "my-channel-01",
    "type": "web_hook",
    "address": "https://yourdomain.com/webhook",
    "expiration": 1893456000000
  }'
```

### 응답 예시

```json
{
  "kind": "api#channel",
  "id": "my-channel-01",
  "resourceId": "o3hgv1538sdjfh",
  "resourceUri": "https://www.googleapis.com/drive/v3/files?...",
  "expiration": "1893456000000"
}
```

나중에 채널을 중지하려면 `resourceId` 값을 저장해 두세요.

## 수신 요청 헤더

Google이 여러분의 엔드포인트로 알림을 전달할 때, `POST` 요청에는 다음과 같은 사용자 정의 헤더가 포함됩니다:

| 헤더 | 설명 |
|--------|-------------|
| `X-Goog-Channel-ID` | 등록 시 지정한 채널 `id`. 어떤 watch가 알림을 트리거했는지 식별하는 데 사용하세요. |
| `X-Goog-Resource-State` | 발생한 변경 유형. 일반적인 값: `sync`(초기 확인), `add`, `update`, `remove`, `trash`, `untrash`, `change`. |
| `X-Goog-Changed` | 변경된 속성의 쉼표로 구분된 목록(예: `content,properties`). `update` 알림에 존재합니다. |
| `X-Goog-Resource-ID` | 지켜보는 리소스에 대한 Google의 내부 식별자. |
| `X-Goog-Resource-URI` | 변경된 리소스의 API URL. |
| `X-Goog-Message-Number` | 채널의 각 메시지에 대한 단조 증가 정수. sync 메시지는 항상 `1`입니다. |

<Note>
  알림 본문은 의도적으로 **비어 있습니다** — Google은 무언가 변경되었다고 알려주지만, 무엇이 변경되었는지는 알려주지 않습니다. `X-Goog-Resource-URI` 헤더를 사용해 후속 API 요청을 보내고 업데이트된 리소스를 가져와야 합니다.
</Note>

## 채널 중지

알림 수신을 중지하고 만료 전에 채널을 해제하려면, 중지 엔드포인트로 `POST` 요청을 보내세요:

```http
POST https://www.googleapis.com/drive/v3/channels/stop
```

```bash
curl -X POST \
  "https://www.googleapis.com/drive/v3/channels/stop" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "my-channel-01",
    "resourceId": "o3hgv1538sdjfh"
  }'
```

성공적인 응답은 빈 본문과 함께 HTTP `204 No Content`를 반환합니다. 채널을 중지한 후 Google은 즉시 해당 채널에 대한 알림 전달을 중단합니다.

## 채널 만료 및 갱신

모든 watch 채널은 만료됩니다 — 여러분이 지정한 `expiration` 타임스탬프에서 또는 Google 자체의 최댓값(API에 따라 다름)에서. 채널이 만료되면 Google은 알림 전송을 중지하며, 새 채널을 등록할 때까지 변경 사항을 놓치게 됩니다.

**권장 갱신 전략:**

1. 각 채널을 등록할 때 반환된 `expiration` 값을 저장하세요.
2. 만료 **최소 24시간 전에** 채널을 다시 등록하도록 작업을 예약하세요.
3. 새 채널을 성공적으로 등록한 후 기존 채널을 중지하세요.

```bash
# 새 채널 ID와 업데이트된 만료 시간으로 다시 등록
curl -X POST \
  "https://www.googleapis.com/drive/v3/files/watch" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "my-channel-02",
    "type": "web_hook",
    "address": "https://yourdomain.com/webhook",
    "expiration": 1925000000000
  }'
```

<Tip>
  고유 채널 ID를 생성하려면 UUID 생성기(예: macOS/Linux의 `uuidgen`)를 사용하세요. 이전 채널이 중지되기 전에 같은 ID를 재사용하면 충돌이나 중복 알림이 발생할 수 있습니다.
</Tip>
