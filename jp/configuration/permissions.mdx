Google アカウントを使ってサードパーティのアプリやサービスにサインインしたり、それらにデータへのアクセスを許可したりすると、これらのアプリはアカウントの特定部分へのアクセスを付与する権限トークンを受け取ります。時間が経つにつれて、もう使っていない接続済みアプリが数十件も蓄積されることがあります。不要な権限を定期的に確認して取り消すことは、アカウントのセキュリティとプライバシーを守るうえで最も効果的な対策の 1 つです。

## 接続済みアプリを確認する

アカウントのダッシュボードの **セキュリティ** セクションから、現在 Google アカウントにアクセスできるすべてのアプリを確認できます。

<Steps>
  <Step title="Google アカウントを開く">
    [myaccount.google.com](https://myaccount.google.com) にアクセスし、サインインします。
  </Step>
  <Step title="セキュリティに移動する">
    左サイドバーの **セキュリティ** をクリックします。
  </Step>
  <Step title="アカウントにアクセスできるサードパーティのアプリを開く">
    **サードパーティのアプリとサービスとの接続** セクションまでスクロールし、**すべての接続を確認** をクリックします。
  </Step>
  <Step title="リストを確認する">
    アクセスが許可されているすべてのアプリと、最終アクセス日、および各アプリが保持している権限が表示されます。
  </Step>
</Steps>

<Note>
  「Google でログイン」を使ってサインインしたアプリも、プログラム的に API アクセスが付与されたアプリも、同じページに表示されます。どちらのタイプも同じページから確認・取り消しが可能です。
</Note>

## アクセスを取り消す

アプリを使わなくなった場合、または見覚えのない接続済みアプリを見つけた場合は、直ちにアクセスを取り消してください。

<Steps>
  <Step title="接続済みアプリに移動する">
    [myaccount.google.com](https://myaccount.google.com) から、**セキュリティ** → サードパーティアプリの下の **すべての接続を確認** に移動します。
  </Step>
  <Step title="削除するアプリを選ぶ">
    アクセスを取り消したいアプリをクリックします。
  </Step>
  <Step title="権限を確認する">
    そのアプリに付与されているスコープのリストを読みます。これは、そのアプリがアクセスできるデータを正確に示しています。
  </Step>
  <Step title="すべての接続を削除をクリックする">
    **[アプリ名] とのすべての接続を削除** をクリックし、プロンプトが表示されたら確定します。
  </Step>
  <Step title="削除を確認する">
    そのアプリは接続済みアプリのリストに表示されなくなり、取り消されたトークンでアカウントにアクセスすることができなくなります。
  </Step>
</Steps>

<Warning>
  アクセスを取り消すと、アプリのアクセストークンは即座に無効化されます — そのアプリはあなたの Google データを読み書きできなくなります。ただし、アプリがすでに自身のシステムにダウンロード・保存したデータは自動的には削除されません。アプリ側のプライバシー設定を確認するか、開発者に連絡してデータ削除を依頼してください。
</Warning>

## OAuth スコープ

OAuth スコープは、アプリが Google アカウントに対して何を許可されているかを正確に定義します。アプリがアクセスを要求する際、特定の機能に対応するスコープ文字列のリストを指定します。サードパーティのアプリケーションにアクセスを許可する前に、要求されるスコープを必ず確認してください。

スコープ文字列は次の形式に従います。

```text
https://www.googleapis.com/auth/[service].[permission-level]
```

例:

```text
https://www.googleapis.com/auth/drive.readonly
```

このスコープはアプリが Google ドライブのファイルを読み取ることを許可しますが、作成、変更、削除はできません。

### よく使われる OAuth スコープ

| スコープ | アクセスレベル | アプリができること |
|---|---|---|
| `https://www.googleapis.com/auth/drive.readonly` | 読み取り専用 | ドライブ内のファイルを閲覧・ダウンロード |
| `https://www.googleapis.com/auth/drive` | フルアクセス | ドライブ内の任意のファイルを作成、編集、削除 |
| `https://www.googleapis.com/auth/gmail.readonly` | 読み取り専用 | すべての Gmail メッセージと設定を読み取り |
| `https://www.googleapis.com/auth/gmail.send` | 送信のみ | 代理でメールを送信 |
| `https://www.googleapis.com/auth/gmail.modify` | 読み書き | メールの読み取り、送信、削除、管理 |
| `https://www.googleapis.com/auth/calendar.readonly` | 読み取り専用 | カレンダーの予定を閲覧 |
| `https://www.googleapis.com/auth/calendar` | フルアクセス | カレンダー予定を作成、編集、削除 |
| `https://www.googleapis.com/auth/userinfo.email` | プロフィール | メールアドレスにアクセス |
| `https://www.googleapis.com/auth/userinfo.profile` | プロフィール | 基本的なプロフィール情報にアクセス |
| `openid` | ID | OpenID Connect で ID を検証 |

<Warning>
  アプリを完全に信頼しており、そのレベルのアクセスが明確に必要でない限り、`https://www.googleapis.com/auth/drive` や `https://www.googleapis.com/auth/gmail.modify` のような広範なスコープの付与は避けてください。アプリの機能を満たす最も制限的なスコープを常に優先してください。ドライブからファイルを読み取るだけのアプリは、決して完全な書き込みアクセスを要求すべきではありません。
</Warning>

<Tip>
  Google API を使って独自のアプリを構築する際は、最小権限の原則に従ってください。アプリが本当に必要とするスコープだけを要求してください。これはユーザーの信頼を高め、アプリの認証情報が万一漏えいした場合のセキュリティリスクも低減します。
</Tip>

## Workspace 管理者の権限

Google Workspace の組織を管理している場合、ユーザーが業務アカウントに接続できるサードパーティアプリを制御する追加のコントロールがあります。これらの設定は **Google Admin コンソール** から管理します。

<Steps>
  <Step title="Admin コンソールを開く">
    Workspace の管理者認証情報で [admin.google.com](https://admin.google.com) にサインインします。
  </Step>
  <Step title="セキュリティ → API の制御に移動する">
    **セキュリティ** → **アクセスとデータ管理** → **API の制御** に移動します。
  </Step>
  <Step title="ドメイン全体のアプリアクセスを管理する">
    **サードパーティアプリのアクセスを管理** をクリックし、組織内のユーザーが接続したすべての OAuth アプリを確認します。
  </Step>
  <Step title="アプリの信頼設定を構成する">
    各アプリについて、信頼レベルを設定できます。
    - **信頼済み** — ユーザーは要求される任意のスコープを付与できます
    - **限定** — ユーザーは制限なしとしてマークされた Google サービスへのアクセスのみを付与できます
    - **ブロック** — 組織内のどのユーザーもこのアプリに接続できません
  </Step>
  <Step title="組織全体のデフォルトを設定する">
    **アプリのアクセス制御** の下で、信頼されていないアプリへのアクセスをユーザーがデフォルトで付与できるかどうかを構成します。
  </Step>
</Steps>

| 管理者制御 | 説明 |
|---|---|
| **アプリごとの信頼レベル** | 個別の OAuth アプリを組織向けに細かく許可またはブロック |
| **ドメイン全体の委任** | サービスアカウントに、ユーザーの代わりに動作するための組織全体のアクセスを付与 |
| **アプリのアクセス制御のデフォルト** | 信頼されていないサードパーティアプリに対する組織全体のポリシーを設定 |
| **監査ログ** | どのユーザーが、いつ、どのアプリを認可したかを確認 |

<Note>
  ドメイン全体の委任 (DWD) は、サービスアカウントに組織内の任意のユーザーになりすます権限を付与します。DWD は本当に必要な場合にのみ使用し、この権限を付与されたサービスアカウントを定期的に監査してください。
</Note>
