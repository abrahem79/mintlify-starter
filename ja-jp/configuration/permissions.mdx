Google アカウントを使ってサードパーティのアプリやサービスにサインインするとき、または、それらのアプリにあなたのデータへのアクセスを認可するとき、それらのアプリはあなたのアカウントの特定部分へのアクセスを付与する権限トークンを受け取ります。時間の経過とともに、もう使っていない接続済みアプリが数十個蓄積されることがあります。不要な権限を定期的に確認・取り消すことは、アカウントのセキュリティとプライバシーを保護する最も効果的な方法の一つです。

## 接続されたアプリを表示する

Google アカウントに現在アクセスしているすべてのアプリは、アカウントダッシュボードの **セキュリティ** セクションで確認できます。

<Steps>
  <Step title="Google アカウントを開く">
    [myaccount.google.com](https://myaccount.google.com) にアクセスしてサインインします。
  </Step>
  <Step title="セキュリティに移動する">
    左サイドバーで **セキュリティ** をクリックします。
  </Step>
  <Step title="アカウントアクセス権を持つサードパーティアプリを開く">
    **サードパーティのアプリとサービスとの接続** セクションまでスクロールし、**すべての接続を表示** をクリックします。
  </Step>
  <Step title="リストを確認する">
    アクセスが付与されているすべてのアプリと、最終アクセス日、各アプリが保持している権限が表示されます。
  </Step>
</Steps>

<Note>
  「Google でサインイン」を使ってサインインしたアプリは、プログラマティックに API アクセスを付与されたアプリと一緒にここに表示されます。どちらのタイプも同じページから確認・取り消しができます。
</Note>

## アクセスを取り消す

アプリを使わなくなった場合や、接続されたアプリに見覚えがない場合は、すぐにそのアクセスを取り消すべきです。

<Steps>
  <Step title="接続されたアプリに移動する">
    [myaccount.google.com](https://myaccount.google.com) から、サードパーティアプリの **セキュリティ** → **すべての接続を表示** に移動します。
  </Step>
  <Step title="削除するアプリを選択する">
    アクセスを取り消したいアプリをクリックします。
  </Step>
  <Step title="権限を確認する">
    アプリに付与されたスコープのリストを読みます。これにより、アプリがどのデータにアクセスできるかが正確に表示されます。
  </Step>
  <Step title="すべての接続を削除をクリックする">
    **[アプリ名] とのすべての接続を削除** をクリックし、プロンプトが表示されたら確認します。
  </Step>
  <Step title="削除を確認する">
    アプリは接続されたアプリのリストから消え、取り消されたトークンでアカウントにアクセスする機能を失います。
  </Step>
</Steps>

<Warning>
  アクセスを取り消すとアプリのアクセストークンは直ちに無効になります — アプリはあなたの Google データを読み書きできなくなります。ただし、アプリが既に自身のシステムにダウンロードまたは保存したデータは自動的に削除されません。データ削除をリクエストするには、アプリ独自のプライバシー設定を確認するか、開発者に連絡してください。
</Warning>

## OAuth スコープ

OAuth スコープは、アプリが Google アカウントで何を行えるかを正確に定義します。アプリがアクセスをリクエストする際、特定の機能にマッピングされるスコープ文字列のリストを指定します。サードパーティアプリケーションにアクセスを付与する前に、リクエストされたスコープを必ず確認してください。

スコープ文字列は次の形式に従います:

```text
https://www.googleapis.com/auth/[service].[permission-level]
```

例:

```text
https://www.googleapis.com/auth/drive.readonly
```

このスコープは、アプリが Google Drive のファイルを読み取ることを許可しますが、作成、変更、削除はできません。

### よくある OAuth スコープ

| スコープ | アクセスレベル | アプリができること |
|---|---|---|
| `https://www.googleapis.com/auth/drive.readonly` | 読み取り専用 | Drive 内のファイルの表示とダウンロード |
| `https://www.googleapis.com/auth/drive` | 完全アクセス | Drive 内のあらゆるファイルの作成、編集、削除 |
| `https://www.googleapis.com/auth/gmail.readonly` | 読み取り専用 | すべての Gmail メッセージと設定の読み取り |
| `https://www.googleapis.com/auth/gmail.send` | 送信のみ | あなたに代わってメールを送信 |
| `https://www.googleapis.com/auth/gmail.modify` | 読み書き | メールの読み取り、送信、削除、管理 |
| `https://www.googleapis.com/auth/calendar.readonly` | 読み取り専用 | カレンダーイベントの表示 |
| `https://www.googleapis.com/auth/calendar` | 完全アクセス | カレンダーイベントの作成、編集、削除 |
| `https://www.googleapis.com/auth/userinfo.email` | プロフィール | メールアドレスへのアクセス |
| `https://www.googleapis.com/auth/userinfo.profile` | プロフィール | 基本プロフィール情報へのアクセス |
| `openid` | ID | OpenID Connect による ID 確認 |

<Warning>
  アプリケーションを完全に信頼し、その水準のアクセスに明確な必要性がない限り、`https://www.googleapis.com/auth/drive` や `https://www.googleapis.com/auth/gmail.modify` などの広範なスコープを付与するのは避けてください。アプリの機能を満たす最小限のスコープを常に優先してください。Drive からファイルを読み取るだけのアプリが、Drive の完全な書き込みアクセスをリクエストするべきではありません。
</Warning>

<Tip>
  Google API を使って独自のアプリケーションを構築する際は、最小権限の原則に従ってください: アプリが本当に必要とするスコープのみをリクエストしてください。これによりユーザーの信頼が構築され、アプリの認証情報が漏洩した場合のセキュリティリスクが低減されます。
</Tip>

## Workspace 管理者権限

Google Workspace 組織を管理している場合、ユーザーが仕事アカウントに接続できるサードパーティアプリを統制するための追加コントロールがあります。これらの設定は **Google 管理コンソール**から管理します。

<Steps>
  <Step title="管理コンソールを開く">
    Workspace 管理者の認証情報で [admin.google.com](https://admin.google.com) にサインインします。
  </Step>
  <Step title="セキュリティ → API コントロールに移動する">
    **セキュリティ** → **アクセスとデータ管理** → **API の制御** に移動します。
  </Step>
  <Step title="ドメイン全体のアプリアクセスを管理する">
    **サードパーティ製アプリのアクセスを管理** をクリックすると、組織内のユーザーが接続したすべての OAuth アプリが表示されます。
  </Step>
  <Step title="アプリの信頼設定を構成する">
    各アプリについて、その信頼レベルを設定できます:
    - **信頼済み** — ユーザーは要求されたスコープをすべて付与できる
    - **制限付き** — ユーザーは制限なしとしてマークされた Google サービスへのアクセスのみ付与できる
    - **ブロック** — 組織内のどのユーザーもこのアプリを接続できない
  </Step>
  <Step title="組織全体のデフォルトを設定する">
    **アプリのアクセス制御** の下で、ユーザーがデフォルトで信頼されていないアプリへのアクセスを付与できるかどうかを設定します。
  </Step>
</Steps>

| 管理者コントロール | 説明 |
|---|---|
| **アプリごとの信頼レベル** | 組織向けに個々の OAuth アプリを細かく許可またはブロック |
| **ドメイン全体の委任** | サービスアカウントに組織全体でユーザーに代わって動作するアクセスを付与 |
| **アプリアクセス制御のデフォルト** | 信頼されていないサードパーティアプリに対する組織全体のポリシーを設定 |
| **監査ログ** | どのユーザーがいつどのアプリを承認したかを確認 |

<Note>
  ドメイン全体の委任(DWD)は、サービスアカウントに組織内の任意のユーザーになりすます能力を付与します。DWD は絶対に必要な場合にのみ使用し、このレベルのアクセスが付与されているサービスアカウントを定期的に監査してください。
</Note>
