Google のような信頼性の高いサービスでも、時折問題が発生することがあります — 予期しないエラーコードを返す API、機能停止した同期、通らないサインインなどです。このガイドでは、Google の製品と開発者プラットフォーム全体で最も一般的な問題を、それぞれを診断・解決する明確な手順とともに順を追って解説します。

<Tip>
  個々の問題のトラブルシューティングを行う前に、[Google Workspace ステータスダッシュボード](https://www.google.com/appsstatus) を確認して、1 つ以上の Google サービスに影響する現在進行中の障害がないか確認してください。多くのサインイン、同期、API の問題は、自然に解決する一時的なインフラインシデントが原因です。
</Tip>

## API エラーコード

Google API がエラーを返した際は、HTTP ステータスコードとエラーメッセージを合わせて、何が問題だったかを正確に伝えます。以下の表は、最も一般的なエラーレスポンスとその対処方法をまとめたものです:

| HTTP ステータス | エラーコード | 意味 | 対処方法 |
|---|---|---|---|
| **400** | `INVALID_ARGUMENT` | リクエストが不正、または無効なパラメーターを含む | リクエストボディとクエリパラメーターを API リファレンスと照合する。必須フィールドの欠落や不正なデータ型がないか確認する |
| **401** | `UNAUTHENTICATED` | リクエストに有効な認証情報が含まれていない | OAuth トークンを更新するか、リクエストヘッダーに API キーが含まれていることを確認する。認証情報が失効していないか確認する |
| **403** | `PERMISSION_DENIED` | 認証済みアカウントにこのアクションを実行する権限がない | 必要な OAuth スコープが付与されていること、API が Cloud プロジェクトで有効になっていること、リソースの共有設定を確認する |
| **429** | `RESOURCE_EXHAUSTED` | この API のクォータまたはレート制限を超過した | 指数バックオフとリトライロジックを実装する。必要に応じて Cloud Console からクォータ増加をリクエストする |
| **500** | `INTERNAL` | Google のサーバーで予期しないエラーが発生 | 指数バックオフでリクエストをリトライする。エラーが持続する場合は [Google Cloud のステータス](https://status.cloud.google.com) ページを確認する |

<Note>
  すべての Google API エラーレスポンスには、`code`、`message`、`status` フィールドを持つ JSON ボディが含まれます。最も実用的な診断情報を得るには、HTTP ステータスコードだけでなく、常にエラーレスポンスボディ全体をログに記録してください。
</Note>

## サインインできない

Google アカウントにサインインできない場合は、以下の手順を順に行ってください:

<Steps>
  <Step title="Caps Lock とキーボードレイアウトを確認する">
    パスワードは大文字と小文字を区別します。パスワードを再入力する前に、Caps Lock がオフになっていること、正しいキーボード言語レイアウトを使っていることを確認してください。
  </Step>
  <Step title="パスワードをお忘れの場合を使う">
    サインインページで **パスワードをお忘れの場合?** をクリックします。Google は復旧用メールアドレスまたは電話番号に確認コードを送信します。コードを入力して本人確認し、新しいパスワードを作成します。
  </Step>
  <Step title="2 段階認証の方法を確認する">
    2 段階認証プロセス(2SV)を有効にしていて認証コードを受信できない場合は、電話に電波があり、Google Authenticator アプリ(または他の TOTP アプリ)が時刻同期された正しいコードを表示していることを確認してください。2SV デバイスへのアクセスを失った場合は、保存されたバックアップコードを使うか、[accounts.google.com/signin/recovery](https://accounts.google.com/signin/recovery) でアカウント復旧をリクエストしてください。
  </Step>
  <Step title="アカウント停止を確認する">
    Google が不審なアクティビティやポリシー違反を検出した場合、アカウントが一時的に停止されている可能性があります。この場合、サインインページに明確なメッセージが表示されます。画面の指示に従って停止に異議を申し立てるか、本人確認を行ってください。
  </Step>
  <Step title="別のブラウザまたはデバイスで試す">
    ブラウザ拡張機能、キャッシュされた認証情報、または破損した Cookie がサインインを妨げることがあります。ローカルの問題を切り分けるため、シークレット / プライベートウィンドウや別のブラウザからサインインしてみてください。
  </Step>
</Steps>

## Google Drive の同期問題

コンピュータと Google Drive の間でファイルが同期されない、または Drive for Desktop が動作しなくなった場合は、以下の手順に従ってください:

<AccordionGroup>
  <Accordion title="ストレージクォータを確認する">
    Google アカウントのストレージが満杯になっている場合、Drive は新しいファイルの同期を停止し、変更のアップロードに失敗することがあります。[one.google.com/storage](https://one.google.com/storage) にアクセスして使用量を確認してください。上限を超えている場合は、Gmail、Drive のゴミ箱、または Google Photos から不要なファイルを削除するか、Google One プランにアップグレードしてください。
  </Accordion>

  <Accordion title="インターネット接続を確認する">
    Drive for Desktop の同期には安定したインターネット接続が必要です。ブラウザを開いてウェブページを読み込むことで接続を確認してください。接続が断続的な場合、同期は一時停止し、接続が安定すると自動的に再開されます。
  </Accordion>

  <Accordion title="Drive for Desktop を再起動する">
    システムトレイ(Windows)またはメニューバー(macOS)の Drive for Desktop アイコンをクリックし、**終了** を選択します。アプリケーションフォルダまたはスタートメニューからアプリを再起動します。クライアントを再起動すると、同期状態を再チェックし、多くの一時的な問題を解決できます。
  </Accordion>

  <Accordion title="Google アカウントを再リンクする">
    アプリが認証エラーを表示している場合、アカウントを再リンクする必要があるかもしれません。Drive for Desktop の設定を開き、**アカウント** に移動し、Google アカウントでサインアウトして再度サインインします。これにより、同期済みファイルに影響を与えずに認証情報が更新されます。
  </Accordion>

  <Accordion title="ファイルパスの長さや命名の問題を確認する">
    Drive for Desktop は、システム制限(Windows では 260 文字)を超えるパスや、OS でサポートされない文字を含むファイル名を持つファイルの同期を拒否することがあります。問題のあるファイルの名前を変更するか、より短いパスに移動し、Drive for Desktop のエラーログで具体的なファイル名を確認してください。
  </Accordion>
</AccordionGroup>

## API クォータ超過(429)

`429 RESOURCE_EXHAUSTED` エラーを受け取ることは、アプリケーションが短時間に多すぎるリクエストを送信した、または日次のクォータ制限に達したことを意味します。対処方法は以下のとおりです:

### 指数バックオフを実装する

失敗したリクエストをすぐにリトライするのではなく、各リトライの間に徐々に長い間隔で待機します。これにより、API が負荷下にある間にクライアントがハンマリングするのを防ぎ、クォータウィンドウがリセットする時間を与えます。

```python
import time
import random

def api_request_with_backoff(request_func, max_retries=5):
    for attempt in range(max_retries):
        try:
            return request_func()
        except Exception as e:
            if "429" in str(e) and attempt < max_retries - 1:
                wait = (2 ** attempt) + random.uniform(0, 1)
                print(f"Rate limited. Retrying in {wait:.2f} seconds...")
                time.sleep(wait)
            else:
                raise
```

### クォータ増加をリクエストする

アプリケーションが恒常的にクォータ制限に達している場合、Google Cloud Console から増加をリクエストできます:

<Steps>
  <Step title="Cloud Console を開く">
    [console.cloud.google.com](https://console.cloud.google.com) にアクセスしてプロジェクトを選択します。
  </Step>
  <Step title="APIs & Services → 割り当てとシステム制限に移動する">
    **APIs & Services** → **割り当てとシステム制限** に移動し、スロットリングされている API でフィルタリングします。
  </Step>
  <Step title="増やしたいクォータを選択する">
    特定のクォータ(例:「1 日あたりのクエリ数」または「1 分あたりのリクエスト数」)を見つけ、その隣のチェックボックスをクリックして、**割り当てを編集** をクリックします。
  </Step>
  <Step title="リクエストを送信する">
    希望する新しいクォータ値と簡単な理由を入力します。Google は通常、2〜3 営業日以内にクォータ増加リクエストを審査します。
  </Step>
</Steps>

## 検索結果が更新されない

ウェブページに変更を加えたのに更新が Google Search の結果に表示されない場合、遅延はほぼ常に Google のクロールとインデックスのパイプラインによるものであり、エラーではありません。

<AccordionGroup>
  <Accordion title="インデックスの遅延について理解する">
    Google のクローラー(Googlebot)がページを訪問した後、インデックスが更新されてそれらの変更が検索結果に表示されるまでには、さらに時間がかかります。ほとんどのサイトでは、このプロセスは数日から数週間かかります。新しいサイトや権威の低いページは、そもそも最初にクロールされるまでに長い時間がかかることがあります。
  </Accordion>

  <Accordion title="Google のキャッシュバージョンを確認する">
    Google が最後にインデックスしたページのバージョンは、Google 検索で `cache:yourdomain.com/page` を検索することで確認できます。キャッシュされたバージョンが古い場合、Google はまだページを再クロールしていないだけです。
  </Accordion>

  <Accordion title="Search Console から再インデックスをリクエストする">
    特定のページの更新を急ぐ必要がある場合は、[Google Search Console](https://search.google.com/search-console) の **URL 検査** ツールを使用します。URL を貼り付けて **インデックス登録をリクエスト** をクリックすると、Googlebot にできるだけ早く再クロールするよう要求できます。即時の結果は保証されませんが、クロールキュー内でその URL の優先度が上がります。
  </Accordion>

  <Accordion title="robots.txt と noindex タグを確認する">
    ページが誤ってインデックス化からブロックされていないことを確認します。`robots.txt` ファイルが Googlebot による URL のクロールを許可していること、そしてページに `<meta name="robots" content="noindex">` タグがないことを確認してください。いずれかがあると、コンテンツは検索結果に表示されません。
  </Accordion>
</AccordionGroup>

<Warning>
  同じ URL に対する再インデックスのリクエストを頻繁に行っても、プロセスが速くなることはありません。Google のインデックスパイプラインは自動的に管理されており、重複したリクエストを送信してもクロールの優先度がさらに上がることはありません。
</Warning>
