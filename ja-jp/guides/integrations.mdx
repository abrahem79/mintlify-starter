Google は、Drive、Gmail、Sheets、Calendar、Maps などのコアサービスの大半を、あらゆるアプリケーションから呼び出せる REST API で公開しています。最初の API リクエストを書く前に、アプリがどのように認証するかを決める必要があります: 公開データにはシンプルな API キー、サインインしたユーザーに代わって操作するには OAuth 2.0、または自動化されたサーバー間ワークフローにはサービスアカウントを使用します。このガイドでは、それぞれのオプションを説明し、セットアップの手順を順を追って解説します。

## 認証方式を選択する

適切な認証方式は、あなたの統合が何を行い、誰のデータにアクセスするかによって決まります。

| 認証方式 | 典型的な用途 | 使用するタイミング | ユーザーの同意が必要か |
|---|---|---|---|
| **API キー** | 公開データの読み取り(Maps、YouTube メタデータなど) | 機密性のない、公開されているリソースにアクセスする | いいえ |
| **OAuth 2.0** | サインインした Google ユーザーに代わって操作 | ユーザーの Drive ファイル、Gmail、Calendar などを読み書きする | はい — ユーザーが権限を付与する必要あり |
| **サービスアカウント** | 人間のユーザーが関与しないサーバー間の自動化 | バックエンドジョブ、データパイプライン、組織所有リソースへのアクセス | いいえ |

## OAuth 2.0 フロー

OAuth 2.0 は、パスワードを共有することなく、ユーザーがアプリケーションに Google データへの限定的なアクセスを付与するための標準です。認可コードフローを実装するには、以下の手順に従います。

<Steps>
  <Step title="Cloud Console で OAuth クライアント ID を作成する">
    [Google Cloud Console](https://console.cloud.google.com) を開き、**APIs & Services → 認証情報** に移動し、**認証情報を作成 → OAuth クライアント ID** をクリックします。**ウェブアプリケーション**(またはアプリに合ったプラットフォーム)を選択し、承認済みリダイレクト URI を追加します。
  </Step>
  <Step title="同意画面を設定する">
    **APIs & Services → OAuth 同意画面** に移動します。アプリ名、サポートメール、そしてアプリが要求するスコープを入力します。スコープはアプリがどの Google データにアクセスできるかを正確に定義します — アプリが必要とする最小限のみをリクエストしてください。
  </Step>
  <Step title="ユーザーを Google の認可 URL にリダイレクトする">
    ユーザーが Google アカウントを接続したい場合、`client_id`、要求する `scope`、`redirect_uri`、`response_type=code` を含む Google の認可エンドポイントにリダイレクトします。Google は設定した同意画面を表示します。
  </Step>
  <Step title="認可コードをトークンと交換する">
    ユーザーが承認すると、Google は短期間有効な `code` パラメーターとともに `redirect_uri` にリダイレクトします。サーバーサイドの POST リクエストを、コード、`client_id`、`client_secret`、`redirect_uri` とともに `https://oauth2.googleapis.com/token` に送信し、`access_token` と(`offline` アクセスを要求した場合は)`refresh_token` を受け取ります。
  </Step>
  <Step title="Bearer トークンで API を呼び出す">
    すべての API リクエストの `Authorization` ヘッダーに `access_token` を含めます。アクセストークンは 1 時間で失効するので、`refresh_token` を使用して、ユーザーに再度プロンプトを出さずに新しいものを自動的に取得します。
  </Step>
</Steps>

## サービスアカウント

サービスアカウントは、個々のユーザーではなくアプリケーションに属する特別な Google アカウントです。秘密鍵で認証するため、バックエンドサービス、スケジュールされたジョブ、対話型ユーザーがいないあらゆるワークフローに最適です。

1. Cloud Console で **IAM と管理 → サービスアカウント** に移動し、**サービスアカウントを作成** をクリックします。
2. アカウントに分かりやすい名前を付け、必要に応じて必要な最小の権限を反映した IAM ロールを付与します。
3. サービスアカウントを開き、**鍵** タブに移動し、**鍵を追加 → 新しい鍵を作成** をクリックし、**JSON** を選択します。鍵ファイルを直ちにダウンロードしてください — 再度ダウンロードすることはできません。
4. JSON 鍵を安全に保管し([セキュリティガイド](/guides/security) のベストプラクティスを参照)、適切な Google クライアントライブラリを使ってサーバーサイドのコードで読み込みます。

サービスアカウントに特定の Google Drive フォルダまたは Sheets ファイルへのアクセスを許可するには、そのリソースをサービスアカウントのメールアドレス(Cloud Console で確認可能)と、人間のユーザーと共有するのとまったく同じように共有します。

## API を呼び出す

アクセストークンを取得したら、HTTP リクエストの `Authorization` ヘッダーに `Bearer` トークンとして添付します。以下は、ユーザーの Google Drive 内のファイルを一覧表示する例です:

```bash
curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  "https://www.googleapis.com/drive/v3/files"
```

`YOUR_ACCESS_TOKEN` を、OAuth フローで受け取ったトークン、またはサービスアカウントキーで JWT に署名して取得したトークンで置き換えます。レスポンスは、認証済みプリンシパルがアクセスできるファイルのリストを含む JSON オブジェクトです。

<Note>
トークンのスコープ、リフレッシュフロー、トークンの取り消しの処理に関する完全なリファレンスについては、[認証 API リファレンス](/api/authentication) を参照してください。
</Note>

## 人気の統合

  <Card title="Google Drive API" icon="hard-drive">

  </Card>
  <Card title="Gmail API" icon="envelope">

  </Card>
  <Card title="Google Sheets API" icon="table">
    スプレッドシートデータの読み書き、セルの書式設定、名前付き範囲の管理を行います。軽量なデータストレージ、レポートダッシュボード、フォームからシートへのパイプラインによく使われます。
  </Card>
  <Card title="Google Calendar API" icon="calendar">
    カレンダーイベントの作成、更新、削除、出席者の管理を行います。スケジューリングシステムの同期、ミーティング招待の送信、空き時間ツールの構築に使用できます。
  </Card>
