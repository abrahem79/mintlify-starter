Google の REST API へのすべてのリクエストは認証が必要です。Google は 3 つの主要な認証メカニズムをサポートしています: 公開データへのアクセス用の API キー、ユーザーの代理として動作するための OAuth 2.0 Bearer トークン、そしてサーバー間統合のためのサービスアカウント認証情報です。適切なメカニズムの選択は、アクセスするデータの種類と、フローに人間のユーザーが関わるかどうかで決まります。

## API キー

API キーは最もシンプルな認証方式です。プロジェクトを Google に識別させますが、ユーザーコンテキストを持たないため、**公開データにアクセスする API**(Programmable Search API など)にのみ適しています。

すべてのリクエストで、`key` クエリパラメーターとして API キーを渡します:

```http
GET https://www.googleapis.com/customsearch/v1?q=example&key=YOUR_API_KEY&cx=YOUR_CX
```

**curl の例:**

```bash
curl "https://www.googleapis.com/customsearch/v1?q=openai&key=YOUR_API_KEY&cx=YOUR_CX_ID"
```

<Tip>
  [Google Cloud Console](https://console.cloud.google.com/apis/credentials) で API キーを生成・管理してください。各キーを特定の API とリファラー URL に制限しておくと、キーが漏洩した際の影響範囲を抑えられます。
</Tip>

## OAuth 2.0 Bearer トークン

アプリケーションが Google Drive のファイル、Gmail のメッセージ、Calendar のイベントなど、**ユーザー所有のデータ**にアクセス・変更する必要がある場合は、OAuth 2.0 を使用する必要があります。ユーザーが OAuth 同意フローを完了すると、アプリケーションはアクセストークンを受け取り、これをすべてのリクエストの `Authorization` ヘッダーに含めます。

```http
Authorization: Bearer ACCESS_TOKEN
```

アクセストークンはデフォルトで **3600 秒(1 時間)** で有効期限が切れます。アプリケーションは付随するリフレッシュトークンを保存し、ユーザーに再度プロンプトを表示せずに新しいアクセストークンを取得するために使用する必要があります。詳細は下記の [トークンの更新](#token-refresh) を参照してください。

**curl の例:**

```bash
curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  "https://www.googleapis.com/drive/v3/files"
```

## サービスアカウント認証情報

サービスアカウントは、個々のユーザーではなくアプリケーションに属する特別な Google アカウントです。**サーバー間**のシナリオ用に設計されています — 例えば、ユーザー操作なしにスケジュールで Google Sheets を読み取るバックエンドジョブなどです。

サービスアカウントとして認証する方法:

1. [Google Cloud Console](https://console.cloud.google.com/iam-admin/serviceaccounts) でサービスアカウントを作成し、JSON キーファイルをダウンロードします。
2. サービスアカウントに必要な IAM ロール(例: `roles/drive.reader`)を付与します。
3. Google クライアントライブラリまたは署名済み JWT を使用して、キーを短命なアクセストークンと交換します。

**例: curl を使用してサービスアカウントキーをアクセストークンと交換する**

```bash
# 1. google-auth-library をインストールするか、oauth2 トークンエンドポイントを直接使用します。
# 以下は、Python の google-auth ライブラリを使った最もシンプルな 2-legged JWT フローです。
# インストール: pip install google-auth requests

python3 - <<'EOF'
from google.oauth2 import service_account
import google.auth.transport.requests

SCOPES = ["https://www.googleapis.com/auth/drive.readonly"]
credentials = service_account.Credentials.from_service_account_file(
    "service-account-key.json", scopes=SCOPES
)
request = google.auth.transport.requests.Request()
credentials.refresh(request)
print("Access token:", credentials.token)
EOF
```

アクセストークンを取得したら、OAuth 2.0 と同じように Bearer トークンとして渡します:

```bash
curl -H "Authorization: Bearer ACCESS_TOKEN" \
  "https://www.googleapis.com/drive/v3/files"
```

<Warning>
  サービスアカウントの JSON キーファイルは安全に保管し、決してソース管理にコミットしないでください。漏洩の疑いがある場合はすぐにキーをローテーションしてください。
</Warning>

## スコープ

OAuth 2.0 スコープは、アクセストークンが付与する権限を正確に定義します。認可ステップでスコープをリクエストし、ユーザーは Google の同意画面で一覧を確認します。アプリケーションが実際に必要とするスコープのみをリクエストしてください — 過度に広範なスコープをリクエストするとユーザーの信頼を損ない、アプリの検証時に却下される可能性があります。

| スコープ | 付与されるアクセス |
|-------|----------------|
| `https://www.googleapis.com/auth/drive.readonly` | ユーザーの Google Drive 内のすべてのファイルへの読み取り専用アクセス。 |
| `https://www.googleapis.com/auth/drive` | ユーザーの Google Drive への完全な読み書きアクセス。 |
| `https://www.googleapis.com/auth/gmail.readonly` | ユーザーの Gmail メッセージと設定への読み取り専用アクセス。 |
| `https://www.googleapis.com/auth/calendar` | ユーザーの Google Calendar への完全な読み書きアクセス。 |
| `openid` | OpenID Connect 経由でユーザーを認証し、安定したユーザー ID を取得します。 |
| `email` | ユーザーのプライマリ Google アカウントのメールアドレスにアクセスします。 |
| `profile` | ユーザーの基本プロフィール情報(名前、写真、ロケール)にアクセスします。 |

## トークンの更新

アクセストークンの有効期限が切れたら、Google のトークンエンドポイントに `POST` リクエストを送信して、リフレッシュトークンを新しいトークンと交換します:

```bash
curl -X POST https://oauth2.googleapis.com/token \
  -d "client_id=CLIENT_ID" \
  -d "client_secret=CLIENT_SECRET" \
  -d "refresh_token=REFRESH_TOKEN" \
  -d "grant_type=refresh_token"
```

成功レスポンスには、新しいアクセストークンとその有効期限が含まれます:

```json
{
  "access_token": "ya29.A0ARrdaM...",
  "expires_in": 3600,
  "token_type": "Bearer"
}
```

| フィールド | 説明 |
|-------|-------------|
| `access_token` | 以降の API リクエストで使用する新しい Bearer トークン。 |
| `expires_in` | トークンが失効するまでの秒数(通常は `3600`)。 |
| `token_type` | 常に `"Bearer"`。 |

新しい `access_token` を保存し、アプリケーション内で以前のトークンを置き換えます。リフレッシュトークン自体は、ユーザーがアクセスを取り消すか、Google によって無効化されない限り有効です。

<Warning>
  OAuth の `client_secret` をクライアントサイドのコード(JavaScript バンドル、モバイルアプリ、パブリックリポジトリなど)に埋め込まないでください。漏洩すると、攻撃者があなたのアプリケーションになりすまし、OAuth フローを乗っ取り、あなたに代わってユーザーデータにアクセスできてしまいます。トークン交換は必ず安全なバックエンドサーバー上で行ってください。
</Warning>
