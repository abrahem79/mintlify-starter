حساب Google الخاص بك هو المفتاح لبريدك الإلكتروني ومستنداتك والبنية التحتية السحابية وبيانات اعتماد API — مما يجعله أحد أكثر الأصول قيمة والأكثر استهدافًا التي تديرها. يتطلب تأمينه إغلاق حسابك بمصادقة قوية والتعامل مع مفاتيح API وبيانات اعتماد حساب الخدمة التي تعتمد عليها تطبيقاتك بنفس العناية التي تعطيها لكلمة المرور. يغطي هذا الدليل الخطوات الأساسية لتقوية كليهما.

## التحقق بخطوتين

يضيف التحقق بخطوتين (2SV) دليل هوية ثاني فوق كلمة مرورك، بحيث لا تكون كلمة مرور مسروقة وحدها كافية للوصول إلى حسابك. يوصي Google باستخدام تطبيق مصادقة كعامل ثانٍ لأنه يولد رموزًا بدون اتصال بالإنترنت وليس عرضة لهجمات تبديل SIM بالطريقة التي تكون بها الرسائل النصية القصيرة.

<Steps>
  <Step title="افتح My Account">
    انتقل إلى [myaccount.google.com](https://myaccount.google.com) وسجّل الدخول إذا طُلب منك.
  </Step>
  <Step title="انتقل إلى Security">
    انقر على **Security** في لوحة التنقل اليسرى.
  </Step>
  <Step title="ابدأ إعداد التحقق بخطوتين">
    تحت قسم **How you sign in to Google**، انقر على **2-Step Verification**، ثم انقر على **Get started**.
  </Step>
  <Step title="اختر العامل الثاني الخاص بك">
    سيقترح Google أقوى طريقة متاحة لحسابك. للحصول على أفضل أمان، اختر **Authenticator app** — امسح رمز QR باستخدام Google Authenticator أو أي تطبيق متوافق مع TOTP (Authy، 1Password، إلخ). بدلاً من ذلك، يمكنك استخدام مفتاح أمان الأجهزة (FIDO2/WebAuthn) للحصول على حماية أقوى.
  </Step>
  <Step title="أكد واحفظ رموز النسخ الاحتياطي">
    أكمل مطالبة التحقق، ثم قم بتنزيل **رموز النسخ الاحتياطي** وتخزينها في موقع آمن. تتيح لك هذه الرموز لمرة واحدة استعادة الوصول إذا فقدت جهاز العامل الثاني الخاص بك.
  </Step>
</Steps>

## قيود مفتاح API

يمكن استخدام مفتاح API غير مقيد من قِبل أي شخص يحصل عليه، من أي تطبيق، لاستدعاء أي واجهة Google API مُفعّلة في مشروعك. تُضيّق القيود نطاق الضرر إذا تم كشف مفتاح.

| نوع القيد | كيفية تعيينه | المثال |
|---|---|---|
| **مراجع HTTP** | في Cloud Console: **Credentials → Edit key → Application restrictions → HTTP referrers** | السماح فقط بـ `https://yourdomain.com/*` بحيث يُرفض المفتاح إذا تم استخدامه من أي موقع آخر |
| **عناوين IP** | في Cloud Console: **Credentials → Edit key → Application restrictions → IP addresses** | السماح فقط بعنوان IP الثابت لخادمك (مثل `203.0.113.42`) بحيث يعمل المفتاح من خلفيتك فقط |
| **قيد API** | في Cloud Console: **Credentials → Edit key → API restrictions → Restrict key** | تقييد المفتاح لواجهة API واحدة (مثل Maps JavaScript API) بحيث لا يمكن استخدامه لاستدعاء Gmail أو Drive |

طبّق جميع الطبقات الثلاث حيثما أمكن ذلك: قيّد بواسطة المرجع أو IP *و*اقفل المفتاح فقط على واجهات API التي يحتاجها فعليًا.

## تدوير مفاتيح API

حتى مع وضع القيود، يجب عليك تدوير المفاتيح دوريًا أو فورًا إذا كنت تشك في أن مفتاحًا قد تم اختراقه.

1. في [Cloud Console](https://console.cloud.google.com)، انتقل إلى **APIs & Services → Credentials**.
2. انقر على **Create Credentials → API key** لإنشاء مفتاح جديد بنفس القيود مثل القديم.
3. قم بتحديث تكوين تطبيقك لاستخدام المفتاح الجديد وتأكد من أن كل شيء يعمل بشكل صحيح.
4. عد إلى صفحة Credentials، انقر على قائمة تجاوز المفتاح القديم (**⋮**)، وحدد **Delete**. سيتوقف المفتاح القديم عن العمل على الفور.

تجنب فجوة في الخدمة من خلال التأكد من نشر المفتاح الجديد والتحقق منه *قبل* حذف المفتاح القديم.

## فحص الأمان

يمنحك Security Checkup من Google نظرة عامة مخصصة على موقف أمان حسابك في مكان واحد. قم بزيارة [myaccount.google.com/security-checkup](https://myaccount.google.com/security-checkup) لمراجعة:

- **أحداث الأمان الأخيرة** — عمليات تسجيل الدخول غير المألوفة أو تغييرات كلمة المرور.
- **أجهزتك** — كل جهاز مسجل الدخول حاليًا إلى حسابك، مع خيار إزالة أي جهاز لا تعرفه.
- **وصول تطبيق الطرف الثالث** — التطبيقات والخدمات التي مُنحت وصول OAuth إلى حسابك، حتى تتمكن من إلغاء أي واحدة لم تعد تستخدمها.
- **حالة التحقق بخطوتين** — تأكيد أن عاملك الثاني نشط والطريقة التي تستخدمها.
- **إعدادات Gmail وDrive** — عناوين إعادة التوجيه، وحسابات المندوب، وإعدادات المشاركة التي قد تعرض بياناتك للخطر.

قم بإجراء Security Checkup مرة واحدة على الأقل كل ربع سنة، وفورًا بعد أي اشتباه في اختراق الحساب.

<Warning>
لا تلتزم أبدًا بمفاتيح API أو أسرار عميل OAuth أو ملفات JSON لحساب الخدمة إلى الكود المصدري — ولا حتى في مستودع خاص. سجل Git دائم، ويمكن جعل المستودعات عامة عن طريق الخطأ، ويحصد الماسحون الآليون بيانات الاعتماد باستمرار من المستودعات العامة. خزّن الأسرار في متغيرات البيئة أو مدير أسرار مخصص بدلاً من ذلك، وأضف أنماط ملفات بيانات الاعتماد (مثل `*.json` و`.env`) إلى `.gitignore` قبل التزامك الأول.
</Warning>

<Tip>
لأحمال الإنتاج، استخدم [Google Cloud Secret Manager](https://cloud.google.com/secret-manager) لتخزين بيانات الاعتماد وإصدارها وتدقيق الوصول إليها. يتكامل Secret Manager بشكل أصلي مع Cloud Run وCloud Functions وGKE عبر ارتباطات IAM، لذلك يمكن لخدماتك استرداد الأسرار في وقت التشغيل دون كتابتها إلى القرص أو خبزها في صور الحاويات.
</Tip>
