يعرض Google مجموعة واسعة من واجهات REST البرمجية التي تشغّل كل شيء من البحث والإنتاجية إلى البنية التحتية السحابية والتعلم الآلي. سواء كنت تبني تطبيق ويب أو عميل هاتف محمول أو خدمة خلفية، فإن هذه الواجهات تمنحك وصولاً برمجيًا إلى منصة Google باستخدام طلبات HTTP و JSON القياسية. يغطي هذا الدليل المفاهيم الأساسية التي تحتاجها قبل إجراء أول استدعاء لك.

## عنوان URL الأساسي

يتم تقديم جميع واجهات Google REST البرمجية من عنوان URL أساسي مشترك:

```text
https://www.googleapis.com
```

بعض واجهات API لها أسماء مضيفين مخصصة (على سبيل المثال، `https://people.googleapis.com`)، لكن الغالبية تتبع النمط `https://www.googleapis.com/{api}/{version}/{resource}`.

## إصدارات API

تستخدم واجهات Google البرمجية **إصدارات قائمة على المسار**. يظهر جزء الإصدار مباشرةً بعد اسم API في مسار URL، على سبيل المثال:

| API | بادئة نقطة النهاية ذات الإصدار |
|-----|-----------------------------|
| Custom Search | `https://www.googleapis.com/customsearch/v1` |
| Drive | `https://www.googleapis.com/drive/v3` |
| OAuth userinfo | `https://www.googleapis.com/oauth2/v2` |

عندما يصدر Google إصدارًا رئيسيًا جديدًا، يظل الإصدار السابق متاحًا في مساره الأصلي حتى يتم الإعلان عن موعد نهائي رسمي لإيقاف الاستخدام. استهدف دائمًا الإصدار المستقر الأحدث لعمليات التكامل الجديدة.

## تنسيق الطلب

يجب أن يتبع كل استدعاء API هذه الاتفاقيات:

- **الطريقة** — استخدم فعل HTTP المناسب للعملية (`GET`، `POST`، `PUT`، `PATCH`، `DELETE`).
- **نوع المحتوى** — قم بتضمين `Content-Type: application/json` على الطلبات التي تحمل نصًا.
- **التفويض** — مرر بيانات الاعتماد في رأس `Authorization` كرمز Bearer، أو عبر معامل الاستعلام `key` للطلبات المصادَق عليها بمفتاح API:

```http
Authorization: Bearer YOUR_ACCESS_TOKEN
Content-Type: application/json
```

- **النص** — يجب أن تكون نصوص الطلبات JSON صالحة. يجب أن تكون القيم المنطقية `true`/`false` (وليس سلاسل نصية)، ويجب أن تتبع الطوابع الزمنية تنسيق RFC 3339.

## تنسيق الاستجابة

تعيد الاستجابات الناجحة رموز حالة HTTP `2xx` ونص JSON. تتبع معظم نقاط النهاية المجمّعة مغلفًا قياسيًا:

```json
{
  "kind": "drive#fileList",
  "nextPageToken": "abc123",
  "items": [
    { "id": "1BxiM...", "name": "Report.pdf" }
  ]
}
```

- **`kind`** — سلسلة نصية ذات مساحة اسم تحدد نوع المورد (مثل `customsearch#search`، `drive#file`).
- **`items`** — مصفوفة من كائنات الموارد التي تعيدها عمليات القوائم.
- **`nextPageToken`** — موجود عند وجود المزيد من صفحات النتائج؛ مرره كـ `pageToken` في الطلب التالي.

## حدود المعدل

تختلف حدود المعدل حسب API ويتم تطبيقها لكل مشروع وكل مستخدم. عند تجاوز الحد، تعيد واجهة API الحالة HTTP `429 Too Many Requests`. يجب عليك تنفيذ التراجع الأسي ومنطق إعادة المحاولة في عميلك.

<Tip>
  راجع [دليل استكشاف الأخطاء وإصلاحها](/help/troubleshooting) للحصول على استراتيجيات إعادة المحاولة الموصى بها وإرشادات حول طلب زيادات في الحصة للأحمال ذات الحجم الكبير.
</Tip>

## استجابات الخطأ

تتبع جميع أخطاء API بنية JSON متسقة، مما يجعل من السهل تحليلها ومعالجتها برمجيًا:

```json
{
  "error": {
    "code": 403,
    "message": "The caller does not have permission",
    "status": "PERMISSION_DENIED"
  }
}
```

| الحقل | الوصف |
|-------|-------------|
| `error.code` | رمز حالة HTTP للخطأ. |
| `error.message` | وصف قابل للقراءة البشرية لما حدث بشكل خاطئ. |
| `error.status` | سلسلة رمز خطأ قابلة للقراءة الآلية. |

تشمل قيم الحالة الشائعة `PERMISSION_DENIED`، و`NOT_FOUND`، و`INVALID_ARGUMENT`، و`UNAUTHENTICATED`، و`RESOURCE_EXHAUSTED`.
