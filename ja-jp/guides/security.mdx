Google アカウントは、メール、ドキュメント、クラウドインフラ、API 認証情報への鍵であり、あなたが管理する最も価値があり、頻繁に狙われる資産の 1 つです。それを保護するには、強力な認証でアカウントをロックダウンし、アプリケーションが依存する API キーとサービスアカウント認証情報を、パスワードと同じ注意深さで扱う必要があります。このガイドでは、両方を強化するための必須ステップを説明します。

## 2 段階認証プロセス

2 段階認証プロセス(2SV)は、パスワードの上に第二の ID 証明を追加するため、盗まれたパスワードだけではアカウントにアクセスできなくなります。Google は認証アプリを第二要素として使用することを推奨しています。認証アプリはオフラインでコードを生成し、SMS のような SIM スワップ攻撃に対して脆弱ではないためです。

<Steps>
  <Step title="マイアカウントを開く">
    [myaccount.google.com](https://myaccount.google.com) にアクセスし、必要に応じてサインインします。
  </Step>
  <Step title="セキュリティに移動する">
    左側のナビゲーションパネルで **セキュリティ** をクリックします。
  </Step>
  <Step title="2 段階認証プロセスのセットアップを開始する">
    **Google へのログイン方法** セクションで **2 段階認証プロセス** をクリックし、**使ってみる** をクリックします。
  </Step>
  <Step title="第二要素を選択する">
    Google はアカウントで利用可能な最も強力な方法を提案します。最高のセキュリティのため、**認証アプリ** を選択してください — Google Authenticator や任意の TOTP 対応アプリ(Authy、1Password など)で QR コードをスキャンします。より強力な保護のため、ハードウェアセキュリティキー(FIDO2/WebAuthn)を使用することもできます。
  </Step>
  <Step title="確認しバックアップコードを保存する">
    検証プロンプトを完了し、**バックアップコード** をダウンロードして安全な場所に保管します。これらのワンタイムコードは、第二要素デバイスを紛失した場合にアクセスを回復するためのものです。
  </Step>
</Steps>

## API キーの制限

制限のない API キーは、それを入手した誰でも、あらゆるアプリケーションから、あなたのプロジェクトで有効化されている任意の Google API を呼び出せてしまいます。制限をかけることで、キーが漏洩した場合の影響範囲を狭められます。

| 制限タイプ | 設定方法 | 例 |
|---|---|---|
| **HTTP リファラー** | Cloud Console: **認証情報 → キーを編集 → アプリケーションの制限 → HTTP リファラー** | `https://yourdomain.com/*` のみを許可し、他のサイトから使用されるとキーを拒否 |
| **IP アドレス** | Cloud Console: **認証情報 → キーを編集 → アプリケーションの制限 → IP アドレス** | サーバーの静的 IP(例: `203.0.113.42`)のみ許可し、バックエンドからのみキーを機能させる |
| **API の制限** | Cloud Console: **認証情報 → キーを編集 → API の制限 → キーを制限** | キーを 1 つの API(例: Maps JavaScript API)に制限し、Gmail や Drive の呼び出しに使用できないようにする |

可能な限り 3 つのレイヤーすべてを適用してください: リファラーまたは IP で制限し、*さらに*、キーを実際に必要な API のみにロックしてください。

## API キーのローテーション

制限をかけていても、キーは定期的に、あるいはキーが侵害された疑いがある場合はすぐにローテーションしてください。

1. [Cloud Console](https://console.cloud.google.com) で、**APIs & Services → 認証情報** に移動します。
2. **認証情報を作成 → API キー** をクリックし、古いキーと同じ制限で新しいキーを生成します。
3. アプリケーションの設定を更新して新しいキーを使うようにし、すべてが正しく動作することを確認します。
4. 認証情報のページに戻り、古いキーのオーバーフローメニュー(**⋮**)をクリックし、**削除** を選択します。古いキーはすぐに動作を停止します。

古いキーを削除する*前*に、新しいキーがデプロイされ検証されていることを確認して、サービスの中断を避けてください。

## セキュリティ診断

Google のセキュリティ診断は、アカウントのセキュリティ状況をパーソナライズされた形で 1 か所にまとめて表示します。[myaccount.google.com/security-checkup](https://myaccount.google.com/security-checkup) にアクセスして、以下を確認しましょう:

- **最近のセキュリティイベント** — 見覚えのないログインやパスワード変更。
- **お使いのデバイス** — 現在アカウントにログインしているすべてのデバイス。見覚えのないものは削除できます。
- **サードパーティアプリのアクセス** — アカウントへの OAuth アクセスが付与されているアプリとサービス。使わなくなったものは取り消せます。
- **2 段階認証プロセスの状態** — 第二要素が有効であることと、使用している方法の確認。
- **Gmail と Drive の設定** — データを露出させる可能性のある転送アドレス、代理アカウント、共有設定。

セキュリティ診断は、少なくとも四半期に 1 回実行し、アカウント侵害が疑われた直後にも実行してください。

<Warning>
API キー、OAuth クライアントシークレット、サービスアカウントの JSON ファイルをソースコードにコミットしないでください — 非公開リポジトリでもです。Git 履歴は永続的で、リポジトリは誤って公開されることがあり、自動化されたスキャナーはパブリックリポジトリから継続的に認証情報を収集しています。代わりに環境変数か専用のシークレットマネージャーにシークレットを保存し、認証情報ファイルのパターン(`*.json`、`.env` など)は最初のコミット前に `.gitignore` に追加してください。
</Warning>

<Tip>
本番ワークロードには、[Google Cloud Secret Manager](https://cloud.google.com/secret-manager) を使用して認証情報を保存、バージョン管理、監査アクセスしてください。Secret Manager は IAM バインディングを介して Cloud Run、Cloud Functions、GKE とネイティブに統合されるため、サービスはディスクに書き込んだりコンテナイメージに焼き付けたりすることなく、実行時にシークレットを取得できます。
</Tip>
